# Durable provision controller development

Status: CL-F25-03 checkpoint B implements a private first-provision controller; it is not installed in the API/gateway/worker or inventory agent. [ADR 0024](../architecture/decisions/0024-durable-provision-controller.md), [intake](deployment-intents.md), [execution](node-execution.md) and [broker](node-broker.md) define the composition. Existing prototype remains inventory/planning-only.

`DeploymentJobs.prepare` accepts an immutable intake reference and idempotency key from its original current adult session. It issues node-placement and canonical Minecraft provisioning grants through identity, validates both in one identity transaction, obtains trusted qualification outside SQL, then rechecks and persists one control-signed command/lease/audit/reference-only outbox in SQL 0022. No production qualifier is provided; default fails unavailable. Domain port tests use explicit fake qualification/independent approval and do not qualify a game image or host.

Each intake permits one provision command, attempt/fence 1 and at most 30s. Concurrent identical requests return the same operation; a different key conflicts. No automatic retry, lease extension/takeover, lifecycle command, polling or queue consumer is installed. Signed command bytes and private identity grants are retained in PostgreSQL; public views/outbox contain references/status only. `succeeded` describes verified stopped provision resources, not a playable Minecraft server.

Node-signed fetch and permit request purposes bind control/tenant/project/node/credential/job/hash, one-use request ID and a fresh permit nonce where appropriate. The peer certificate hash/lifetime must come from a verified private mTLS connection. The service revalidates current node/key, original session/user/membership and both canonical permissions, policy, unchanged allocated reservation, stop epochs and fresh exact qualification before each fetch/permit. Permits expire within 5s and never outlive the job/session/credential. There are at most 64 recorded requests per job; replay/exhaustion fails closed. Clock rollback, stale proof, cancellation and approval/policy/stop changes deny new effects. A previously issued physical effect cannot be retroactively canceled.

`recordReceipt` verifies the node signature and exact command/tenant/resource/fence binding. Identical replay is idempotent; conflicting receipt is refused. Unknown or expired work retains uncertainty/capacity/ports. `settleExpired` lets a currently authorized adult record expiration metadata without reissuing work; it does not require the original requester to remain active. A late signed success receipt does not clear prior uncertainty. Known compensation/no-dispatch also retains world/storage/port accounting pending future evidence-bound reconciliation. Never edit/drop rows or journals to retry a command.

## Outbound command transport (checkpoint C)

`CommandTransport` is a separate explicit-policy library implementing the executor authority port. It fetches an exact known job/hash, obtains a fresh signed permit for each guard and submits the retained signed receipt. Fixed private HTTPS routes share the existing TLS 1.3/client-certificate/server-pin/bounded JSON/absolute-deadline transport. Response signature/scope/hash/nonce checks apply; command failures are non-retryable and never dispatch another effect automatically. Receipt acknowledgements are scope/hash/state checked under pinned TLS and do not clear uncertainty.

`buildNodeAgentApp` accepts an optional private controller injection for `/node/v1/commands/exchange` and `/node/v1/commands/receipt`. These reject cookie authentication and use the actual authenticated peer certificate; strict contracts allow no arbitrary verb/path/body. The installed `node-main.ts` does **not** inject it, and the inventory CLI has no mutable mode or enable environment variable. Default gateway command routes remain absent. In-process test injection is separate from production authority isolation.

The added real integration journey uses the fifth disposable DB, temporary uninstalled OpenSSL CA/certificates, a loopback mTLS listener, actual signed controller grants/leases/permits, private node journals and real Unix Engine create/inspect. It verifies missing/wrong client certificate, wrong server pin, explicit enabled policy/key/scope/action denial, one stopped scratch-only Redis container, exact replay, receipt settlement/ack replay, retained allocation and exact owned-ID cleanup. The default gateway refuses the command path. Qualification/independent approval and Redis profile are explicitly test-only: no Minecraft image, EULA, persistent world or real host qualification. Harness cleanup captures exact returned IDs/nonce and preserves private evidence on failure; no prune/force/volume/image deletion.

## Remote identity authority (checkpoint D)

[ADR 0025](../architecture/decisions/0025-remote-execution-authority.md) specifies `buildExecutionAuthorityApp` and `RemoteDeploymentAuthorizer`. Both are optional private composition libraries; no installed main/Compose listener or credentials are changed. The identity listener receives its own authority signing key, configured controller **public** key and pinned gateway client certificate; it has no node-control private key or Docker. Gateway authorizer needs runtime/control/TLS plus authority public pin, no identity DB/CSRF secret. Bind any future listener to private transport only.

Each controller-signed check carries exactly the original sealed node/project and server/environment grants over pinned mutual TLS, a fresh nonce and digest; it does not mint new rights or approve infrastructure. Identity validates current original actor/session/membership/permission and returns a separate purpose/key-bound proof with no profile PII or grant body. Proof freshness is at most 2s and distinct from original session expiry. The gateway checks its expiry around SQL and caps node permits to it. Role loss may occur after a proof was issued; each guard makes a fresh check, with no proof cache/retry/fallback. Stop epochs/local stop/fences still outrank scheduling, and already-accepted daemon effects remain uncertain rather than retroactively canceled.

The identity endpoint keeps only bounded read-request nonce retention in memory (1,024 entries/5s). Original grants are checked every time; API restart cannot make a response valid for a newly generated client nonce. Durable command/effect replay evidence remains in PostgreSQL/node journals. Cookies, wrong gateway certificate/control signature, altered grant digest/purpose, expiry and replay deny. Metadata checks/response signing are local inside the identity transaction; no transaction spans the RPC or qualification call.

The actual DB/TLS/Redis integration now runs the gateway controller with `authorizer` and no `auth`; its human methods correctly deny as uninstalled. Checkpoint E replaces the initial test issuer in this journey with API-side `DeploymentAdmissions` and gateway `issueAdmission` using stored sealed authority. No mixed identity/control service is needed in that flow. Installed HTTP/worker/entrypoint wiring still remains; never mount the control key into API. Explicit fake qualification/approval, stopped scratch Redis and temporary uninstalled PKI still do not qualify Minecraft worlds or a deployed host.

## Split human authority admission (checkpoint E)

`DeploymentAdmissions` takes runtime DB, identity service and clock only; it has no control signing key, qualifier, node transport or Docker port. The original current adult/session must still own the exact allocated intake, both canonical scopes and unchanged node/key. Store sealed original grants privately with stop digest, idempotency/body hash and an expiry capped by 120s/session/node credential. Intent/body cannot supply grants, approval, image or command. One intent has one immutable authority record; audit/outbox commit atomically and projections contain references/expiry/optional job ID only. Completed metadata replay rechecks current authority/bindings without repeatedly minting grants. Expiry/clock rollback denies renewed admission; historical read reports expiry without extending it.

A separate gateway with only remote authorizer/runtime/control identity calls `issueAdmission(org, authorityId)`. It loads the sealed pair from immutable PostgreSQL state, verifies current delegated identity rather than trusting queue IDs, checks unchanged stop snapshot/expiry and fresh actual qualification, then signs one command linked by SQL to those exact grants/actor/session/intake/stop. Command cannot outlive the authority record. Independent approval remains a separate qualification requirement; this authority metadata does not accept EULA or approve infrastructure. No outbox publisher/consumer is installed yet and replay never extends or takes over a command lease.

SQL 0023 forces RLS, scoped immutable actor/session/grant-resource/intent bindings and reference-only outbox, with exact job-authority FK/grant/hash/stop/expiry checks. Runtime has SELECT/INSERT only on authority records, not UPDATE/DELETE. They need no row lock because they are immutable; normal FKs protect references. Revert application code while retaining additive schema/history/sealed grants/allocations. Do not drop or reset authority to bypass expiry or release charged worlds/ports. Legacy private `prepare` remains compatible for previous local callers/tests with no authority link; it is not the production API admission interface.

Five additional DB cases cover concurrent one-authority replay/reopen/atomic outbox, gateway single-job issuance, no serialized grants, current adult/tenant/original-session/read/revocation, expiry/default qualifier denial/no release, stop epochs, RLS/immutability/FKs and raw altered sealed-scope/job-link SQL refusal. The actual remote-authority/TLS/Redis journey now begins with this admission and no-identity gateway issuance. Two contract cases reject caller grants/approval and secret/executed projections. Qualifications remain explicit fakes; no HTTP/main/Compose activation or game/world change follows.


## Local HTTP and SDK metadata (checkpoint F)

The API entrypoint now constructs `DeploymentAdmissions` using runtime DB and identity only; it acquires no control key, qualifier or Docker access. Readiness also requires SQL 0023 authority storage. Installed node/gateway entrypoints remain inventory-only. This adds no browser wizard, background issuer, reservation/dispatch endpoint or public physical provisioning action.

| `/api/v1` route | Result |
| --- | --- |
| `POST /servers/provision/admissions` | `202` metadata-only authority operation; strict body `{ intent_id }` and UUID `Idempotency-Key` |
| `GET /servers/provision/admissions/:id` | Historical active/expired authority metadata and optional linked job ID |
| `GET /servers/provision/jobs/:id` | Safe job state, scope/resource references, command digest, lease and receipt state |
| `GET /operations/:id` | Existing management/node operations plus these admission/job projections |

All reads require current adult project `node:deploy` and canonical Minecraft environment `server:provision`, in authenticated organization membership selected by UUID `X-CraftLayer-Organization`. The selector cannot grant membership. Mutations additionally require exact Origin/CSRF and the original initiating actor/session. Replays return the same authority without extending expiry; changed keys/input conflict. Clients cannot submit grants, signatures, commands, images, EULA, approval or qualification assertions. Responses are non-cacheable and omit sealed grants, actor/session identifiers, raw receipts and command bodies. Historical `active` means the stored authority has not expired; it does not establish current execution permission, host qualification or readiness.

`deploymentClient(organization, csrf, signal?)` exposes `admit(intentId, key)`, `admission(id)`, `job(id)` and `operation(id)` using the existing same-origin bounded request transport and strict shared response schemas. OpenAPI documents required organization/idempotency headers and strict request/response shapes. Generic operation lookup advances only on a not-found result; permission or authentication denial stops resolution.

Remote management remains unavailable pending private-entry/MFA qualification. The browser listener does not expose command exchange/receipt or job issuance, and default qualification still denies physical work. Admission requires a previously allocated private intent, so the existing planner/dashboard cannot create an executable deployment through these routes. Expired/abandoned records and allocated ports/world claims remain retained for future evidence-bound reconciliation. Rollback removes the new route/SDK wiring while retaining SQL/history/allocations; no world or Docker rollback applies.

Three real PostgreSQL/API cases verify denied anonymous/child/viewer/foreign/current-revoked access, Origin/CSRF, required headers, strict caller assertions, concurrent replay/atomic records, OpenAPI, actual loopback HTTP/SDK status and receipt projection, default qualification denial, expiry/no extension, retained allocations, absent physical routes and remote blocking. Qualification/approval and prepared reservations are explicit test fakes; these checks do not qualify Minecraft or production process isolation.

## Bounded background issuance and expiry (checkpoint G)

`DeploymentDispatcher` composes private `dispatchPending` and `settleExpiredForNode` with strict operator placement. `tick` performs at most eight denial-only expiry settlements and eight unexpired unissued authority references; `run(signal, observe?)` repeats sequentially at one-second intervals with generic outcomes. A rotating UUID cursor skips blocked records, wraps and resets safely on restart. PostgreSQL's immutable outbox and unique job links supply durability; no Redis delivery, consumption flag or new schema is needed. Concurrent/lost-ack scans cannot issue a second command or renew a lease. Original current authority, independent approval/qualification and stop checks still apply at issuance; absent production qualification denies.

The expiry sweep verifies canonical placement/history and this controller's retained signed command, then marks only overdue issued work uncertain, audits and retains allocation/ports. It can deny expiry after initiating-session revocation, node rotation or a safety stop; it grants no effects or resource release. Ordinary human expiry settlement retains its current permission checks. Late success does not clear uncertainty. Abort is observed between bounded operations; it cannot cancel an already committed metadata issuance or daemon action. Installed main/Compose remains inventory-only. [ADR 0026](../architecture/decisions/0026-deployment-background-dispatch.md) records fairness, recovery and limitations.

The real DB/remote-authority/TLS/scratch-Redis journey now begins with the dispatcher. Four added DB cases cover duplicate scanners/lost worker acknowledgement/reopen/cancellation, denied qualification/revocation/scope/page bounds, cursor progress past a blocked reference and concurrent expiry/late evidence/retained allocation. These do not qualify Minecraft or enable production.
