# ADR 0014 — Runtime authority, bounded simulation and recovery

Status: adopted for authorized Chapter 03, 2026-11-01. The user's continuation request after Chapter 02 authorizes Chapter 03 only. Prior review evidence is accepted for advancement, not independent security certification. Chapter 04 requires its own checkpoint.

Implement `packages/runtime` as a trusted server coordinator with pure graph/state rules in `packages/core` and strict JSON-safe schemas in `packages/contracts`. PostgreSQL owns templates, immutable mission/task snapshots, execution identity, attempts/fences, effect receipts, approvals, events, outbox and stop state. SQL migrations enforce tenant/scope relationships, transition checks and append-only projections; Drizzle describes relationships. No agent framework is introduced.

Use an explicit `simulation` environment and reviewed `fixture.*` task/tool registry for the first end-to-end runtime. It cannot connect a Minecraft client, shell or internet tool. Children cannot access simulation; approved Minecraft child launch remains the adapter/preset work in Chapters 04–05. Existing Minecraft account restrictions are not weakened. The approval primitive demonstrates independent adult approval of an exact immutable action and generation; it does not authorize future deployment/coding tools.

A trusted API coordinator authenticates both current initiating authority and an organization/environment-bound registered worker. Worker tokens, execution grants and provider credentials are never queued. Reference-only queue events are hints: canonical database records and worker binding determine scope. The worker receives bounded action data only after a claim, and revalidates before effects. No identity database credential or provider encryption key is given to workers. Host and trusted API/database administrators remain outside application-error defenses.

Use BullMQ's Redis backend as replaceable at-least-once transport, with PostgreSQL outbox/reconciliation as authority. Pin the selected library version and consult its shipped typings/source plus official docs before integration. Publication and acknowledgements use short transactions and lease/fence checks, with no transaction spanning Redis/HTTP. Schedule bounded round-robin batches across active tenant index rows. Global scheduler/capacity data uses a narrow internal transaction context and never a tenant-facing list/count endpoint.

Default graph bounds: 50 tasks/mission, 10 tool calls/task, two model-plan repairs and three task attempts. Actions have at most ten-second deadlines within a fifteen-second authority lease; heartbeat target five seconds and isolated-action bound twenty seconds. Local watchdogs use monotonic deadlines and deny when control-plane authority cannot be renewed. Persist stop at instance/org/environment/mission scope; clearing never resumes. Cancellation has an explicit `cancelling` state until known effects quiesce; unknown effects stay blocked. This adds a necessary truthful intermediate state to the original lifecycle diagram.

External effects are marked before dispatch and produce stable-key receipts. A lost acknowledgement after a mark is uncertain, even if no physical effect occurred. Never automatically retry an uncertain effect. Fencing protects database commits, not external physics. Actual game/sandbox shutdown and reference-host timing are not claimed by simulation evidence. Provider accounting remains conservative and request replay does not recreate inference after a lost response; runtime persists canonical request IDs and blocks uncertain provider outcomes for review.

Expose scoped REST/CLI and bounded resumable SSE, using authenticated replay and opaque scope-bound cursors. SSE is the first streaming transport; a duplicate WebSocket implementation is unnecessary. Revalidate stream authority, bound output buffers/connections and signal resync when retention invalidates a cursor. No raw prompts, grants, provider keys or chain-of-thought enter projections. Event retention/production backup tooling remains Chapter 09; enforce current storage ceilings rather than claiming an unimplemented purge job.

Primary references consulted: [PostgreSQL 18 locks](https://www.postgresql.org/docs/18/explicit-locking.html), [BullMQ connections](https://docs.bullmq.io/guide/connections), [stalled delivery](https://docs.bullmq.io/guide/jobs/stalled), and [SSE protocol](https://html.spec.whatwg.org/multipage/server-sent-events.html). Library/backend details and measured qualification are recorded in build evidence as each task lands.
