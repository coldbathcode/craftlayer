# ADR 0051 — AI player harness: a named, model-agnostic, budgeted player placed next in the plan

Status: adopted 2026-11-15. The owner asked for it as the next thing to do, answered decisions 8–12, then said "get going" after being told that G0 meant accepting the Chapter 03 review and authorizing Milestone G; that is recorded as both. Plan: [Milestone G](../../plan/G-ai-player.md).

## Context

The owner wants an AI agent that plays in the family world as a named player, takes plain-language instructions, remembers, reasons about the game, runs on any model (main foundation-model providers, OpenRouter or a local Ollama), and stops spending at a set limit. The existing plan reaches in-game agents only at F2, after F1 and Chapter 04 authorization. The older roadmap also places them after the F3 operations phase, and places direct foundation-model adapters at Chapter 07, after the bot chapters.

What exists: the provider gateway with OpenRouter and Ollama adapters, encrypted credentials, a fail-closed router and a reservation ledger in micro-USD with mission/task scopes (Chapter 02). The fleet runtime with durable stop latches, leases and fencing (Chapter 03, review awaiting owner acceptance). Agent tokens and MCP with approval-gated actions (Milestone C). A live server helper with adult-approved allowlist actions (Milestone A). The Chapter 04 specification for a bounded Mineflayer adapter.

## Decision

1. **Order.** Milestone G is the next build milestone in the master plan (ADR 0034 makes the master plan authoritative for order). It carries Chapter 04's tasks (CL-04-01 to CL-04-07) and moves the Anthropic, OpenAI and Gemini adapters forward from Chapter 07. The F3 gate in the older roadmap does not apply to G: G uses no provisioning or lifecycle capability, and the bot never gets server-control rights. The owner's G0 authorization is the Chapter 04 authorization.
2. **Three layers.** Deterministic reflexes and a typed skill library carry out every game effect; the model only chooses skills and arguments through validated tool calls. No raw commands, chat-to-command paths or operator rights.
3. **One gateway for every model.** All calls go through the existing router and ledger. OpenRouter and Kong AI Gateway are the required routes (owner decision 9). Kong is added as an OpenAI-compatible connection to an adult-registered, allowlisted gateway URL with an encrypted Kong consumer credential. A generic OpenAI-compatible connection and direct Anthropic, OpenAI and Gemini adapters follow, all implementing the same normalized contract. Models without tool calling are not offered. Prices come from a provider catalog or an adult-maintained price table with source and date; unknown price means not selectable for paid use.
4. **Per-player budgets.** The ledger gains an AI-player scope with daily and total windows for spend, tokens and calls (starting at $1/day and $10 total, owner decision 9). The scope is reserved before each call, so concurrent calls cannot overshoot. At the limit the brain stops; reflexes keep the body safe; only an adult raises the limit.
5. **Its own process and account.** A player worker app hosts bot sessions, separate from the server helper (ADR 0016), with no RCON, Docker or node credentials. The first AI player signs in with the **owner's own Minecraft Java account** (owner decision 8) through Microsoft's device-code flow. The session is stored encrypted, held only by the player worker, revocable, and never enters prompts. A duplicate-login disconnect means the owner wants the account back: the worker stays off and never reconnects over the owner. A dedicated account can replace the owner's later. A server-side NPC plugin (no account) was rejected because it would run inside the live server with full privileges. Online sign-in and the allowlist stay on.
6. **Memory in PostgreSQL.** Working, episodic and fact memory per AI player and world, bounded and adult-editable. No new vector store; embeddings may later use a local Ollama model behind a separate decision.
7. **Instruction sources.** Only the owner instructs (owner decision 10): dashboard chat, MCP with the owner's agent token, and in-game chat from the owner's *other* identity, matched by account ID because the AI player uses the owner's Java name. All other chat, including children's, is conversation, never instruction (AGENTS rule 8).
8. **Free run of the world, with recovery.** No protected zones by default (owner decision 11); zones remain an option. Attacking players, pets and villagers stays impossible. Every block change is journaled. The AI player joins the family world only after a verified backup and off-server copy exist (AGENTS rule 11: worlds are irreplaceable).
9. **Master tasks for unasked work.** The owner keeps a list of allowed standing tasks with priority and conditions (owner decision 12). When idle the brain picks the highest-priority applicable one; with none, it makes no model calls. Direct owner instructions are not limited to the list.

## Consequences

- Chapter 04's specification stays the engineering source for the bot adapter; Milestone G adds the brain, memory, model choice, conversation and cost monitor around it.
- Chapter 07 shrinks to the providers and compatible endpoints not delivered by G2.
- The first AI player costs no licence but borrows the owner's account: the owner cannot be on Java with it at the same time, and a VPS compromise could misuse the stored session until revoked. Further AI players each need an account; a turnkey multi-bot experience is not promised.
- **G1 (2026-11-15):** Mineflayer supports 26.1, not 26.3. The bot speaks 26.1 and ViaVersion/ViaBackwards on the server translate. Installing them on the family server is a production change needing approval and a verified backup (decision 13). Mineflayer is pinned to an official master commit because the release lacks `tick_end`; the body adds the upstream #4201 tick rule and the float player width (#3911). Details: [AI player runbook](../../development/ai-player.md).
- Real-model evaluation and paid calls run only under the configured limit (decision 3 allows paid models; decision 9 sets $1/day, $10 total). CI uses a scripted fake model and a fake body.
- Kid Mode (F2b) and teams (F2c) build on G's profiles, skills and limits rather than a separate stack.
