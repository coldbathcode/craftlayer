# ADR 0013 — Provider gateway safety and accounting boundary

Status: adopted for authorized Chapter 02, 2026-11-01. Chapter 01 is accepted for advancement by the user's continuation request; this is not independent security certification.

Use shared strict Zod request/result/error/capability/pricing contracts, a server-only `packages/providers` package, direct bounded HTTP transports and deterministic fakes. No additional SDK with hidden retries is required. Prompts cannot select endpoints, credentials, paid fallback, budgets or authority. Tool responses are proposals only; no tool executes in this chapter. Start with bounded nonstreaming text/tool-proposal responses. Unexpected streaming or incomplete responses become uncertain outcomes rather than unaccounted retries.

Pricing uses explicit USD decimal strings at 18 decimal places and integer micro-USD ceilings. Every dimension is present or explicitly unknown. Provenance and freshness are required; a model name/suffix is never cost evidence. Hosted metadata has a maximum five-minute lifetime. Unknown, stale, unsupported or nonzero dimensions fail strict free-only eligibility.

OpenRouter documents request routing preferences and maximum prompt/completion/request/image prices, but those controls do not establish enforcement for every possible ancillary charge. The implemented adapter will send one exact model, disable upstream fallback and optional server features, and apply documented price bounds. Strict hosted free-only remains ineligible without complete enforceable zero-cost evidence; this implementation will not manufacture such evidence. Explicit paid policy remains bounded by every governing scope and reservations. See [routing controls](https://openrouter.ai/docs/guides/routing/provider-selection) and [catalog schema](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties).

Ollama supports local and cloud inference. Only exact operator-approved endpoints, resolved address pins and approved installed models qualify as operator-local. The operator must disable cloud features and confirm the local-only deployment. Reject remote/proxy model metadata and unknown local-model evidence. No local inference smoke, model download or hardware qualification is implied by fake contracts. See [local/cloud API distinction](https://docs.ollama.com/api/introduction), [cloud disable setting](https://docs.ollama.com/faq), and [chat contract](https://docs.ollama.com/api/chat).

Connection secrets use organization/connection/key-version-bound authenticated encryption and a protected versioned key file outside the database/images. Instance endpoint/cost policy is operator-owned, outside organization request bodies. Default Core remains useful with provider support unconfigured, no provider key and no paid spend. Optional provider egress/configuration must be explicit; normal Compose remains private.

The router uses current authenticated execution authority, current connection/key/policy versions, persisted cooldowns and a durable reservation interface before every dispatch/fallback. Chapter 02 introduces a persisted provider stop latch (never reset on restart); Chapter 03 must compose it with mission/world/instance emergency stop and leases before effects. No public arbitrary-prompt generation endpoint is added. API routes administer redacted connections/catalogs/policy/usage only.

Budget counters use stable lock order, tenant-aware references and PostgreSQL authority. Dispatched outcomes with unknown usage retain conservative holds; duplicate idempotency/settlement cannot release them twice. Never hold a database transaction across provider I/O. Each fallback is separately reserved and accounted. A later worker transports identifiers and signed authority, never raw credentials/prompts in queue metadata.

The specification orders router integration before the ledger task. Implement its required reservation interface and test fake first in CL-02-05; production dispatch stays disconnected until the real ledger is wired in CL-02-06. This preserves task order without exposing unreserved calls. Public release, real hosted inference and actual SMTP remain separately authorized actions.

CL-02-02 implements a narrow auth guard which holds current user/session/membership shared locks while a separate runtime-role transaction performs bounded provider SQL and its audit insert. The guard exposes an authenticated principal, never the identity pool/client. No network I/O is permitted in that callback. This serializes authority changes against the SQL decision without giving provider code identity-table privileges; it does not claim a distributed transaction or atomic external network effect.

Default Compose remains provider-unconfigured. Optional provider Compose mounts protected mode-0600 files read-only, runs API with the non-root host UID/GID owning those files and explicitly adds provider egress. Worker/web receive no provider key files. Setup preserves existing generated keys; key removal requires rewrapping and verifying all dependent rows first.

CL-02-03 uses Node 22's native HTTP/TLS client with a fresh validated DNS/address lookup, then pins that address in the actual socket lookup. Hosted resolution is IPv4-only in this slice; approved local IPv4/IPv6 pins are explicit. Redirects, compressed/unexpected content and bodies over 2 MiB are rejected; calls have overall abort/deadline bounds and no automatic retry. Ollama discovery requires an approved tag digest, installed GGUF metadata and declared completion/context support; remote model metadata is rejected. Thinking models require an advertised disabled-thinking option. Generation rechecks the exact installed model fingerprint, sends explicit context/output bounds and returns no raw model template or thinking transcript. Unknown usage stays unknown. See [Node 22 HTTP](https://nodejs.org/download/release/v22.23.3/docs/api/http.html), [Ollama tags](https://docs.ollama.com/api/tags) and [model details](https://docs.ollama.com/api-reference/show-model-details).

CL-02-04 reads bounded catalog subsets for explicit operator-approved canonical model IDs. Auto routers and routing/plugin suffixes are rejected; `:free` is a name only. The documented prompt/completion/request/image fields normalize with explicit units, while omitted ancillary fields remain unknown and unrecognized charges are preserved as unknown names. No complete zero-cost enforcement is inferred. One-model generation disables upstream fallbacks and optional plugins/transforms, applies documented price filters, bounds output/deadlines and performs no SDK retry. Metadata requests carry no credential, and a credential echo in an upstream response is rejected rather than returned or logged. Hosted generation remains ineligible wherever complete cost evidence cannot be established. No actual catalog or generation endpoint was called for verification.

CL-02-05 persists organization/user/project policies, connection cooldowns and an independently cleared provider stop latch. Policy/capability/pricing checks run again at a dispatch barrier after metadata/DNS validation and immediately before the HTTP request. A zero instance or scope spending ceiling requires enforceable zero-cost evidence even if an org turns off its own free-only flag. Every fallback has a separate reservation and current eligibility check. Router behavior is verified with an injected reservation port; production composition exposes administration/catalog operations only until CL-02-06 supplies durable accounting. Redis cooldown caching is not needed for correctness; persisted PostgreSQL state is authoritative.
