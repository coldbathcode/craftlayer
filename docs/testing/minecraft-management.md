## Stage decisions

F0 local gate: MC-02 collector proof, preservation procedure and explicit unknowns. Production F0 remains unverified until permission and real inventory/recovery evidence.

F1 observation preview: MC-01/02/05/06/12 portions applying to observation/registry pass locally; remote use additionally needs qualified TLS/private access/MFA. Mutation and family-ready controls remain unavailable. No bot or Chapter 03 completion dependency.

F2 family-ready: all applicable MC-01–06, MC-08/12 pass, including actual compatible identity/client trials, isolated restore and approved production baseline/remediation before a Contabo claim. Any unresolved identity, allowlist drift, public management port, backup integrity/restore or privilege defect blocks readiness. A failed/unknown check is never a green badge.

F25 provisioning-ready: all MC-01–12 portions applying to provisioning pass on disposable hosts, including all unified §16.9 cases (MC-07 provisioning/conflicts, MC-01/10 auth, MC-05 network, MC-06/09 replay/restart/rollback, MC-03/04 identities, MC-08 backup, MC-02/11 preservation, MC-10 approval, MC-07 quotas/EULA). This prepares a deployable feature; Contabo deployment still needs approved preflight and exact host plan.

F3 full management: additionally qualify adopted lifecycle, redacted logs/metrics, staged update, retained decommission and complete API/MCP parity. Full Core M4 still requires original Chapter 09 release gates.

## Evidence commands and implementation ownership

Existing commands: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:db`, `pnpm test:integration`, `pnpm test:e2e`, `pnpm docs:check`, `pnpm compose:check`. Inspect package.json before each task; integration requires disposable DB setup. No F-specific test scripts exist yet. Add meaningful fixture/integration/browser commands with their owning task, document them before claiming execution, and preserve source blueprint checksum.

Production preservation proof must distinguish game-generated live writes from management effects: use stopped/quiesced snapshot hashes and immutable container/mount/config/state comparisons under approved read access. Do not compare two running-world hashes and assert unchanged. No production test may delete or replace a real world to prove rollback.
